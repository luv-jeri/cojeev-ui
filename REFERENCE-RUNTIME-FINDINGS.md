# Reference runtime conflicts

All three conflicts occur in the **unmodified full catalog**, not only in generated isolation pages. The owner decisions below remain pending; this audit changes no production or reference behavior.

Checked at `aefd2ae10fa7efd15a22ebadd8615f5711e0ffa0`, using isolated Chromium at 1440×1000 with normal motion and fresh storage for each case. The original files were served directly on port 4350, without gate adapters. No runtime errors occurred in the three full-catalog probes. [Measured evidence](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/.work/reference-runtime/results.json>) and [boundary checks](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/.work/reference-runtime/boundaries.json>) are retained locally.

1. **Newly opened Dialog controls miss their morph bodies.** After clicking the catalog's actual “Open dialog” button and waiting 1.8 seconds, Close, Cancel and Save were visible but all three still lacked `data-morph`, `data-auto-morph` and a morph SVG. Buttons/icons were enabled. The hidden-attribute observer reads `window.VAlive.cats()` and silently returns when that object is absent; the shipped runtime exposes `window.VMotion`. This is an actual catalog defect, independent of the export fixture. Sources: [morph.js:326](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/morph.js:326>), [motion.js:54](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/motion.js:54>), [catalog Dialog markup](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/catalog/reg-base-a.js:30>). **Decision:** preserve the exported missing decoration, or restore automatic decoration when a layer opens.

   There is also a distinct **isolation-fixture defect**: `default-default-open-720x480.html` starts with open markup, but `VUI.init` hides every dialog. The directly loaded “open” fixture therefore finishes hidden and non-modal. That does not explain the full catalog's missing descendant bodies after a real click. Sources: [open fixture:5](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/isolation/dialog/default-default-open-720x480.html:5>), [ui.js:330](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/ui.js:330>).

2. **Settings “Off” does not freeze explicit bodies in the full catalog.** A real click changed `VMotion.mode()` to `off`, while rest, reach, merge, hold, jiggle and press stayed enabled. The explicit “alive” Category Tile remained attached and produced four distinct path geometries during real pointer hover. `motion.js` skips its profile application when `VPanel` exists or a saved engine configuration exists; the catalog always loads `VPanel`. This contradicts the unqualified “bodies stay static” wording in ADJUSTER. Sources: [ADJUSTER.md:13](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/docs/ADJUSTER.md:13>), [motion.js:38](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/motion.js:38>), [motion.js:47](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/motion.js:47>), [catalog panel loader:212](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/catalog/index.html:212>). **Decision:** Off overrides authored/workbench motion, or Off retains this limited scope and the contract/control explanation changes.

   This is **not a universal clean-consumer failure**: the original standalone Category Tile demo, with no VPanel or saved profile, set all seven documented flags to false and stayed geometrically static through the same pointer sampling. Imported profiles take the same bypass branch by source inspection; that separate storage case was not replayed. Decorative arm drift and color/spinner updates also have independent guards in [morph.js:209](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/morph.js:209>), [214](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/morph.js:214>) and [229](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/morph.js:229>); this audit does not claim complete coverage of those authored combinations.

3. **The full stylesheet replaces special effect fills with the body color.** In the original catalog's alive Category Tile, the sheen and grain paths retain `fill="url(#v-sheen)"` and `fill="url(#v-grain)"`, but both compute to solid `rgb(245, 216, 103)`. The echo path's `fill="none"` is also overridden, although that echo is hidden in this specimen. The rule `svg.v-morph path { fill: var(--mfill,transparent) }` comes through the actual `vriksha.css` import chain and wins over those SVG attributes. Sources: [components-2.css:460](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/css/components-2.css:460>), [vriksha.css:13](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/css/vriksha.css:13>), [effect construction in morph.js:106](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/js/morph.js:106>). This is a real catalog cascade conflict; an engine-only fixture that omits the full stylesheet cannot represent the exported appearance. **Decision already raised:** preserve the export's flat appearance, or preserve the effect-specific fills.

   The documentation itself disagrees: [ADJUSTER.md:35](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/docs/ADJUSTER.md:35>) documents texture controls, while [AGENT-PROMPT.md:34](</Users/sanjaykumar/Documents/ChatGPT/sahajiv ui/.worktrees/composed/reference/sahajiv-handoff-v4/docs/AGENT-PROMPT.md:34>) calls sheen, grain and `v-alive` retired; nevertheless the full catalog still includes the alive tile. This audit independently confirms the mechanism and that live specimen; it does not repeat or claim ownership of the earlier 147-field/seven-pixel-sample comparison.
