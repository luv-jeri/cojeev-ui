## Analytics contract found in source

It retains only `utm_source`, `utm_medium`, `utm_campaign`, and `utm_content` in memory across SPA navigation. A random anonymous ID is per page load; the persistent item is only the opt-out flag. DNT, GPC, or opt-out discard events; routes under `/feedback-admin/` and `/workspace/` are rejected. Payloads set `referrerPolicy: no-referrer`, disable PostHog person profiles and GeoIP enrichment, and analytics failure does not change the visitor-facing copy result.

Source defaults name the EU PostHog host. The public homepage HTML did not itself contain an ingestion-host or token marker, but client chunks can carry runtime configuration, so this is not a diagnosis of deployed capture. Initial in-app-browser inspection found no accessible organisation for that identity; the later Chrome access recovery below supersedes this access blocker. A deliberate production Button copy showed the UI state `Copied to clipboard.`; a sanitized CDP capture through that action found zero PostHog network requests. This confirms copy UI success only. It does not diagnose configuration or privacy suppression, prove that analytics is off, or establish dashboard receipt. A command copy shows intent only; it does not prove an install. Browser events cannot establish Google/Bing organic attribution without a valid referrer or campaign/source analysis, and they cannot establish a verified consumer build.
